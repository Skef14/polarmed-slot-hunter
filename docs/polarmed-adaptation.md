# Для разработчиков: устройство Polarmed

**Для обычного использования этот документ не нужен.** Начните с [основной инструкции](../README.md).

## Быстрый старт

Нужен **Node.js 18 или новее**. Устанавливать npm-зависимости не требуется.

```sh
npm test
npm run build:polarmed
```

Готовый файл для Tampermonkey: **`dist/polarmed-slot-hunter.user.js`**.

## Где что находится

| Путь | Назначение |
|---|---|
| `adapters/polarmed.js` | Разбор ответов сайта и подготовка полей запросов |
| `adapters/polarmed-platform.js` | Чтение выбора пользователя, запросы к сайту, проверка результата |
| `core/` | Фильтры, цикл поиска, предварительная проверка, координация вкладок |
| `userscript/ui-state.js` | Логика условий поиска |
| `userscript/ui-dom.js` | Кнопка, окна настройки, подтверждения и сообщения |
| `userscript/polarmed-header.js` | Название, версия и адрес сайта для запуска |
| `scripts/build-polarmed.js` | Сборка установочного файла |
| `test/` | Автоматические тесты на выдуманных данных |
| `data-site/` | Только локальные материалы исследования; не публикуются |

Основная команда сборки — **`npm run build:polarmed`**. Не путайте её с техническими сборками других файлов в репозитории.

## Как проходит поиск

1. Прочитать выбранные пациентом поликлинику и специальность.
2. Для режима «Любой врач» получить список врачей специальности.
3. Последовательно проверить талоны до первой подходящей находки.
4. Применить ограничения дат и времени.
5. Показать предварительную проверку без записи.
6. После запуска — записывать сразу либо запрашивать подтверждение на 60 секунд.

Перед отправкой записи повторно проверяются **тот же врач и тот же талон**. Смена пациента, поликлиники или специальности требует новой настройки.

Интервал между проходами — не меньше **20 секунд**. При ограничении сервера или сетевой ошибке включается пауза. Запросы к врачам не отправляются параллельным потоком.

## Какие адреса вызывает адаптер

| Адрес | Для чего |
|---|---|
| `POST /api/doctor_list/` | Врачи выбранной специальности |
| `POST /api/appointment_list/` | Свободные талоны врача |
| `POST /api/signup/` | Подтверждение новой записи |
| `POST /signup/create-appointment/` | Штатное сохранение записи для личного кабинета |
| `GET /profile/` | Проверка результата |

Это жёсткий список разрешённых запросов. **Адреса отмены записи не вызываются.**

### Что важно в ответах сайта

- Свободные талоны сгруппированы по дням: `response[YYYY-MM-DD]`.
- Талон содержит `id`, `date_start` и `date_end`; время — `iso` и `time`.
- Общее расписание `/api/doctor_schedule/` — не список свободных талонов. Подставлять его вместо `/api/appointment_list/` нельзя.
- Счётчик `CountFreeParticipantIE` может запаздывать. Ноль в нём не исключает врача из поиска.
- `history_id` может отсутствовать. В таком случае передаётся пустая строка, без выдуманного идентификатора.
- Рабочий часовой пояс — **UTC+3**. Противоречивые даты отклоняются.

## Как читается выбор пользователя

Основной путь — загруженная модель сайта: `app` или AMD-модуль, доступный через загрузчик страницы.

Если она недоступна, резервный путь использует:

1. Явно выбранный `preset` из адреса страницы.
2. Соответствующую ему запись штатного хранилища Amplify.
3. Выбранные элементы страницы.

**Первый попавшийся пациент из хранилища не выбирается.** Устаревшие, неполные или противоречивые данные блокируют работу.

Персональные поля нужны только в памяти для штатных запросов сайту. Они не должны попадать в настройки, журнал, тесты или сообщения об ошибках.

## Защита от повторной записи

Перед изменяющим запросом сохраняется метка попытки. Она остаётся и после перезагрузки.

- Между вкладками используется **Web Locks**.
- При потере ответа автоматическая повторная запись запрещена.
- Снять блокировку можно только после явного подтверждения пользователем ручной проверки.
- Кнопка остановки не отзывает уже отправленный запрос.

Результат проверяется в личном кабинете по идентификаторам талона, пациента и поликлиники. Если проверка невозможна, нельзя выдавать это за успех.

## Что проверяют тесты

- Разбор ответов, даты, время и фильтры.
- Поиск по специальности и сохранение выбранного врача при подтверждении.
- Смену пациента и других условий.
- Отсутствующую историю обращения при обязательных защитных полях.
- Потерю ответа, повторную попытку, гонку вкладок и остановку поиска.
- Работу кнопки и безопасные ошибки `P_…`.
- Сборку установочных файлов и часть проверок на персональные данные.

> Тесты используют искусственные ответы и имитацию страницы. Они не доказывают, что реальная медицинская запись на сайте прошла успешно. Не создавайте записи ради тестирования.

## Сбор структуры страницы для диагностики

Нужен только при исследовании изменения сайта, не для обычной работы.

1. Выполните `npm run build:inspector`.
2. Установите в Tampermonkey файл `dist/polarmed-site-inspector.user.js`.
3. На нужной странице нажмите **«Polarmed: сохранить структуру»**.
4. Откройте полученный JSON и проверьте его перед передачей.
5. После диагностики отключите сборщик.

Сборщик сохраняет названия полей и безопасную структуру форм. Значения полей, cookie, текст страницы, содержимое хранилища и параметры URL не экспортируются.

Локальные материалы храните в `data-site/`. **Не добавляйте эту папку в Git и не прикладывайте необработанные выгрузки к Issues.**
