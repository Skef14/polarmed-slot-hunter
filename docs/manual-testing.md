# Проверка интерфейса перед выпуском

Этот список — для разработчика. Для установки и поиска талона используйте [основную инструкцию](../README.md).

> **Не создавайте ненужные медицинские записи ради теста и не отменяйте существующие.** Проверки изменяющих запросов выполняйте на выдуманных ответах. Реальную запись проверяйте только при обычном использовании, когда она действительно нужна.

## 1. Сначала автоматические тесты

```sh
npm test
npm run build:polarmed
```

Если тесты не прошли, не публикуйте сборку как проверенную.

## 2. Установка и кнопка

- [ ] Файл `dist/polarmed-slot-hunter.user.js` устанавливается в Tampermonkey.
- [ ] На reg.polarmed.ru видна кнопка **«Охотник: открыть настройки»**.
- [ ] Без выбранной специальности кнопка открывает понятную инструкцию.
- [ ] «Проверить выбор» сразу показывает состояние загрузки.
- [ ] Неудачная проверка показывает причину с кодом `P_…`, без личных данных.
- [ ] После выбора пациента и специальности открывается первый шаг настройки; врач необязателен.

## 3. Условия поиска

- [ ] Доступен вариант **«Любой врач»** выбранной специальности.
- [ ] Если врач выбран на сайте, доступен и поиск только у него.
- [ ] Даты и время сохраняются при переходе назад и вперёд.
- [ ] Поле времени старой записи объяснено как фильтр, а не изменение талона.
- [ ] Предупреждение об отсутствии проверки дороги и других приёмов видно.

## 4. Предварительная проверка — без записи

- [ ] Проверка показывает подходящее время или понятную причину ожидания.
- [ ] У найденного талона показан врач.
- [ ] В личном кабинете не появляется новая запись от самой проверки.
- [ ] Запуск недоступен без галочки подтверждения отчёта.
- [ ] Изменение условий требует новой предварительной проверки.

На этом этапе можно остановиться: **запускать автоматическую запись ради проверки интерфейса не нужно**.

## 5. При действительно нужном поиске

- [ ] После запуска плашка показывает «Ищу слоты».
- [ ] Время последней проверки появляется только после настоящей проверки.
- [ ] Можно открыть окно состояния и остановить поиск.
- [ ] В режиме подтверждения видны врач, время и оставшиеся секунды.
- [ ] После остановки карточка подтверждения не остаётся активной.
- [ ] Перезагрузка либо восстанавливает тот же выбор, либо явно просит выбрать его заново.
- [ ] Смена пациента, поликлиники или специальности не приводит к записи по старой настройке.

## 6. После попытки записи

- [ ] Пользователь получил понятный результат: подтверждение либо просьбу проверить вручную.
- [ ] После потери ответа не происходит автоматической второй записи.
- [ ] Старые талоны не отменялись.
- [ ] Снятие блокировки требует явного подтверждения ручной проверки.
- [ ] Фактические врач, дата и время проверены в личном кабинете.

## Чего не делать

- Не очищать все данные сайта для каждого пункта: можно потерять вход и защиту от дублей.
- Не удалять метку попытки до проверки результата.
- Не считать отсутствие уведомления доказательством отсутствия записи.
- Не прикладывать к отчёту ФИО, полис, cookie, токены или адреса страниц с данными пациента.
