# Как опубликовать обновление

Этот документ — для владельца проекта. Пользователям достаточно [инструкции по обновлению](../README.md#как-обновить-или-удалить).

## 1. Проверьте версию и изменения

- Согласуйте номер версии в `package.json`, `userscript/polarmed-header.js` и README.
- Кратко опишите изменения в [CHANGELOG.md](../CHANGELOG.md).
- Не обещайте то, что не проверялось.

## 2. Запустите тесты и сборку

```sh
npm test
npm run build:polarmed
```

Установочный файл: **`dist/polarmed-slot-hunter.user.js`**.

GitHub Actions повторит проверки после загрузки. Убедитесь, что они завершились успешно.

## 3. Проверьте, какие файлы попадут на GitHub

```sh
git status --short
git diff --stat
```

**Публиковать нельзя:**

- папку `data-site/`;
- данные пациентов и снимки кабинета без обезличивания;
- cookie, токены, `.env`, содержимое хранилища браузера;
- необработанные выгрузки сетевых запросов (`.har`);
- полные ссылки с параметрами пациента.

`.gitignore` не спасёт файл, который уже был принудительно добавлен в Git. Автоматическая проверка тоже не заменяет просмотр списка файлов.

## 4. Загрузите изменения и создайте релиз

- Коммитьте только проверенные файлы.
- Не перезаписывайте чужие изменения принудительной отправкой.
- Вложите в релиз **готовый `.user.js`**, а не архив всей рабочей папки.
- В описании перечислите изменения, ограничения и проведённые проверки.
- Сохраните авторство и текст MIT-лицензии.

Если обновлялась только документация, выпускать новую версию программы необязательно.

## 5. Проверьте установку по ссылке

1. Откройте ссылку установки из README.
2. Убедитесь, что она ведёт на актуальный файл в этом репозитории.
3. Проверьте название и версию в Tampermonkey.

`homepageURL` и `supportURL` должны вести в этот репозиторий. Автоматическое обновление пока не настроено — не обещайте его пользователям.

> `private: true` в package.json защищает от случайной публикации в npm. На публичную доступность GitHub-репозитория это не влияет.
