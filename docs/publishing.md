# Публикация на GitHub

Публикуется userscript, а не расширение из Chrome Web Store.

Перед каждой публикацией:

1. Выполнить `npm test` и `npm run build:polarmed`.
2. Проверить версию в `package.json`, `userscript/polarmed-header.js` и README.
3. Проверить список добавляемых файлов. `data-site/`, cookies, токены, `.env`,
   HAR, личные сообщения, снимки кабинета и параметры пациента публиковать нельзя.
   `.gitignore` не защищает файл, который уже был принудительно добавлен в Git.
4. Не включать `data-site/` в архивы вручную. Релиз можно выпускать с одним
   вложением `dist/polarmed-slot-hunter.user.js` — архив рабочей папки не нужен.
5. Указать в описании релиза реальные изменения, известные ограничения и
   проведённые проверки. Искусственные тесты не называть подтверждением
   успешной записи на реальном сайте.

Текст лицензии и авторство исходного проекта сохраняются. Метаданные
`homepageURL`/`supportURL`, если добавляются, должны указывать на эту адаптацию,
а не отправлять её пользователей в Issues оригинального ЕМИАС-проекта.
Автообновления в скрипте пока отключены: установка и обновление ручные.

GitHub Actions запускает тесты и проверяет, что сборки соответствуют исходникам.
`private: true` в package.json предотвращает случайную публикацию в npm и не
влияет на публичную видимость репозитория GitHub.
